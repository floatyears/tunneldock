# 工作区 MCP 真实调用与 Token 统计规格

## 目标

- 删除审计页固定生成的两条演示记录，调用次数只来自实际执行。
- 捕获 TunnelDock 启动的每个 Pi RPC 进程输出的 `tool_execution_start` 与 `tool_execution_end` 事件，并持久化工具名、参数、结果摘要、状态和耗时。
- 每条记录携带稳定的工作区 ID 和工作区名称，审计页可按工作区筛选，顶部指标随工作区筛选变化。
- 使用 `o200k_base` 对完整 MCP 调用参数和完整工具结果进行本地计数，分别记录输入、输出和总 Token；界面明确这是 MCP 传输 Token，不冒充 ChatGPT 账单 Token。
- 历史文件向后兼容：旧记录缺少新字段时仍可正常载入。

## 完成标准

- 空历史返回空数组，不再生成样例数据。
- 工具开始事件立即生成 `executing` 记录，工具结束事件将同一记录更新为 `success` 或 `error`。
- 不同工作区产生的记录可独立筛选和聚合。
- Token 数由实际完整 JSON 负载计算，结果摘要截断不影响 Token 数。
- 后端记录变化后通知前端刷新，无需依赖重启。
- Rust 测试、TypeScript 构建和 Tauri Rust 测试通过。
